# 週一研究：受試者交付與入組核對

本文件供黃貞穎老師團隊使用。參與者說明請使用 [繁中操作單](participant-start.zh-TW.md)，不要把本文件或分析手冊整份交給參與者。

## 每位受試者要收到什麼

1. `particeps-v1.0.0-rc.14.apk`：本次驗收的正式簽章候選 App。
2. `study.partcfg`：已簽署、以「黃貞穎老師團隊」為研究者的研究設定。
3. `participant-start.zh-TW.pdf`：手機可閱讀的中文操作單，包含可信管道核對用的簽章指紋。
4. 團隊的開始通知與資料交回通知：指定哪個時段按「開始研究」、每天何時交回、交到哪裡，以及聯絡與報酬領取方式。

前三項位於 `output/monday-study/participant-pack/`。可由團隊經既有邀請管道分別傳送兩個檔案及操作說明；若先將整包下載到研究者電腦，請解開後分別提供，避免要求受試者先在手機解壓縮。設定檔約十餘 KB，APK 約 64 MiB。

簽章設定保留目前方案：120 小時；App 使用紀錄為必要來源；前兩天不限速，第 3–5 天 12–17 時雙向各 500 kbps；問卷仍第 3–5 天。使用者尚未指定新的問卷日程，不擅自改為五天。更改任何已簽署內容，必須重新簽署，更新檔案摘要及對應 QR；沿用同一簽署金鑰時，簽章指紋保持相同。不能覆寫已交付的檔案冒充原版本。

研究團隊不列私人電話或 Email。設定中的聯絡方式為「請透過邀請您參與研究的管道聯絡研究團隊。」因此邀請管道必須有人值守，受試者遇到安裝或回收問題時才能得到處理。

## 現在的下載與設定入口

截至 2026-10-03，已實際開啟 [公開參與者頁](https://jacoblincool.github.io/particeps/participant/)：它的「下載 App」仍指向 RC13。GitHub 公開 releases 也尚無 RC14。**本機 RC14 檔案不是公開下載網址，不能把舊官網連結當成本次修正版的入口。**

現有兩份公開 QR 設定檔均可直接下載且摘要相符，但它們是內部試跑設定；其中一份還把 App 使用資料設為可選。不要把舊 QR、舊 `join.txt` 或舊 `.partcfg` 交給正式受試者。

有兩種交付方式：

- **直接交檔**：經團隊指定管道提供本次 APK 與 `study.partcfg`。受試者下載後，從 Particeps 的「選擇研究設定檔」選取檔案；不需要 QR 或設定檔網站。
- **固定公開入口**：先發布並驗證本次 APK 的確切下載位址，再更新官網連結。設定檔則另外放到可直接回 HTTP 200 的 HTTPS 位址，產生綁定確切摘要與簽章指紋的 QR。設定下載端不得重新導向；不能直接拿 GitHub release 的重新導向下載網址作為 QR 的 artifact 位址。

目前沒有替新設定生成 QR，因為尚未指定或發布它的 HTTPS 下載位置。這不影響直接交檔方式。一般手機相機掃描網頁 QR 與 App 內掃描研究 QR 不是同一種入口；提供 QR 時必須附相對應的操作說明。

不要交付研究者私鑰、分析工具、原始 `study.json`、效應分析報表或整個研究者工作目錄。`.partcfg` 才是 App 接受的研究設定；原始 JSON 是研究者的工作檔，並包含完整研究規則。

## 入組身分與時間

目前使用共用設定，`assigned_participant_id` 為空。App 不要求帳號；每次成功匯入會產生一組新的安裝代碼。正式開始後，在「研究說明與我的資料」抄錄安裝代碼，與團隊的匿名研究代碼對照。姓名／聯絡名冊另行保管，不寫進公開網址或設定檔。

使用 `output/monday-study/researcher-templates/enrollment-register.csv` 記錄每部手機的驗收。研究代碼與安裝代碼必須逐一對上。重新匯入產生新代碼時保留舊記錄，不能直接覆蓋同一列。

設定 ID 的日期不會讓研究在週一自動開始。可以事先安裝、匯入與授權，但正式 Start 時段須由團隊通知；開始鍵按下後才起算 120 小時。測試研究應另用測試 instance，先保存測試匯出，再依 App 正常流程清理。不可把正式 Start 當成可隨意重設的測試。

Android 14 以上只是最低條件；本設定還要求陀螺儀、Usage Access、通知與研究 VPN。每部手機都要實際完成授權及開始前檢查，遇到感測器缺失或裝置管理限制須當場處理。

## 每日與最終回收

`upload` 為空，沒有自動上傳。團隊須指定一個實際收件位置、每天回收時間與負責人，並在原邀請管道通知受試者。不能只寫「匯出即可」。

匯出檔名只有 experiment ID 與秒級時間，不能用來判定是哪位參與者；不同手機同秒匯出也可能同名。接收時依研究代碼分資料夾，以不可覆寫方式保存每次檔案，記錄檔案摘要與安裝代碼。

`output/monday-study/researcher-templates/export-receipt-register.csv` 是每日驗證紀錄空白表。收到 `.partexp` 後實際執行密文驗證、materialize 與 usage-report；確認安裝代碼、最新資料時間、來源涵蓋率與研究狀態，再回覆受試者已完成該次回收。截圖或檔案存在都不能替代這一步。

完整命令、缺口判讀與完成回收條件見 [執行手冊](monday-study-runbook.md)。不要因為提前按「完成研究」就把不足 120 小時的資料列成已完成。

## 發送前最後核對

- APK 與 `.partcfg` 摘要符合本次 candidate manifest；簽章設定要求 versionCode 41，RC13 無法加入。
- 受試者操作單與這次設定使用相同的研究團隊名稱及 signer fingerprint。
- 安裝檔由實際邀請管道可下載；至少一部實體手機已走過下載、安裝、檔案匯入、授權、收集、匯出及研究者分析。
- 開始時段、每日收件時間／位置、聯絡值守與報酬領取方式已通知。這些事項目前尚未全部定案。
- 本次模擬器測試不能替代 120 小時實機耐久證據，亦不能替所有廠牌的省電與安裝策略背書。
